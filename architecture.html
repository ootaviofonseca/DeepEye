Core — Agentes (LangGraph / ReAct)

O motor de agentes fica em packages/core/deepeye/agents/. É uma biblioteca Python independente — não importa nada do backend. Pode ser testada isoladamente.

Hierarquia de classes

BaseAgent # agents/base.py — interface abstrata __init__(model, tools, system_prompt, checkpointer) _build_graph() → Any # subclasses implementam ainvoke(input, thread_id, config) astream(input, thread_id, config) └── ReActAgent # agents/react_agent.py _bound_model = model.bind_tools(tools) _build_graph() # StateGraph: agent ⇄ ToolNode _call_model() # trunca contexto, injeta system_prompt _should_continue()# "continue" se tool_calls, "end" caso contrário ├── SupervisorAgent # agents/supervisor.py │ system_prompt injetado dinamicamente por request │ _extract_workflow_final_answer() # short-circuit loop │ └── (SQLAgent, CodeAgent — disponíveis, não na chain principal) AgentFactory # agents/factory.py create_supervisor(tools, system_prompt_template)

Como o LangGraph executa o ReAct loop

react_agent.pydef _build_graph(self):
    workflow = StateGraph(AgentState)          # estado: messages: Annotated[list, add_messages]
    workflow.add_node("agent", self._call_model)   # node 1: chama o LLM
    workflow.add_node("tools", ToolNode(self.tools)) # node 2: executa tool calls
    workflow.set_entry_point("agent")
    workflow.add_conditional_edges(
        "agent", self._should_continue,
        {"continue": "tools", "end": END}         # há tool_calls? → tools; senão → fim
    )
    workflow.add_edge("tools", "agent")            # resultado da tool → de volta ao LLM
    return workflow.compile(checkpointer=self.checkpointer)
max_context_messages=20: se o histórico exceder 20 mensagens, as mais antigas são descartadas antes de chamar o modelo — previne context_length_exceeded. Além disso, a lógica remove AIMessages com tool_calls sem ToolMessages correspondentes para evitar erro 400 na API OpenAI.

SupervisorAgent — injeção dinâmica de contexto

supervisor.pyasync def _call_model(self, state, config):
    # 1. Verifica se WorkflowAgent já produziu final_answer → short-circuit
    final_answer = self._extract_workflow_final_answer(list(state["messages"]))
    if final_answer:
        return {"messages": [AIMessage(content=final_answer)]}

    # 2. Lê contexto de datasources do request config (injetado em agent_tasks.py)
    datasources_context = config["configurable"].get("datasources_context", "No data sources.")
    system_msg = SystemMessage(content=prompt_template.format(
        datasources_context=datasources_context
    ))
    return {"messages": [await self._bound_model.ainvoke([system_msg] + list(messages))]}
Checkpointer: o estado do agente é persistido no PostgreSQL via AsyncPostgresSaver usando thread_id=session_id. Isso permite que o agente continue de onde parou entre requests — memória de longo prazo por sessão.

Resolução de inputs entre nós

engine.py — _resolve_inputs()for edge in incoming:                          # arestas que chegam no nó
    value = context.runs[edge.source.node_id].outputs[edge.source.port_id]
    if edge.condition:                           # aresta condicional?
        if not conditions.require(edge.condition).evaluate(value, context):
            continue
    if edge.transform:                           # transformação de valor?
        value = transforms.require(edge.transform).apply(value, context)
    if target_port.multiple:                      # porta aceita vários upstream?
        inputs.setdefault(port_id, []).append(value)
    else:
        inputs[port_id] = value

Topological sort — Kahn's Algorithm

engine.py — _topological_sort()indegree = {node_id: 0 for node_id in graph.nodes}
for edge in graph.edges.values():
    indegree[edge.target.node_id] += 1

queue = [node_id for node_id, deg in indegree.items() if deg == 0]
order: list[str] = []
while queue:
    node_id = queue.pop(0)   # BFS → ordem respeita dependências
    order.append(node_id)
    for neighbor in adjacency[node_id]:
        indegree[neighbor] -= 1
        if indegree[neighbor] == 0:
            queue.append(neighbor)  # nós sem dependência pendente → mesma "layer"
Paralelismo: nós que chegam ao indegree=0 ao mesmo tempo pertencem à mesma camada de execução e podem ser despachados em paralelo pelo Celery. O engine atual executa em sequência topológica — o paralelismo real é delegado ao runtime Celery/Redis.

BaseNode — contrato de implementação

node/core/base.pyclass BaseNode(ABC):

def register_node_specs(registry: NodeRegistry):
    for module_name in NODE_MODULES:
        importlib.import_module(module_name)       # importa → BaseNode.__subclasses__() cresce
    for node_cls in BaseNode.__subclasses__():
        registry.register(node_cls.spec())        # auto-registro
Para adicionar um nó: crie a classe em app/node/<domínio>/, adicione o path em NODE_MODULES. O nó aparece automaticamente em /api/v1/workflow-nodes e fica disponível ao Planner.

Backend — Celery Task (agent_tasks.py)

Arquivo: packages/backend/app/tasks/agent_tasks.py

É aqui que tudo começa. Quando o usuário envia uma mensagem, a API enfileira esta task no Redis e retorna imediatamente. O worker Celery pega e executa de forma assíncrona.

1. Entrada
AgentInput desempacotado
AgentInput(session_id, user_input, datasource_ids) — Pydantic model. A task Celery recebe como dict e revalida.
2. Persistência
persist_message() + create_chat_turn_record()
Salva a mensagem do usuário no PostgreSQL e cria o registro ChatTurn com status inicial.
3. Sandbox
sandbox_manager.get_or_create_sandbox(session_id)
Cria ou reutiliza o container Docker da sessão. Depois, sync_datasource_files() copia arquivos de datasource para o volume do sandbox.
4. Ferramentas
build_datasources_context() + build_workflow_prompt()
Constrói o contexto textual dos datasources (metadata, schema) e o prompt do WorkflowAgent com o catálogo de nós disponíveis.
create_design_workflow_tool() + create_summarize_workflow_result_tool()
Cria as LangChain tools que o Supervisor pode invocar. Cada tool encapsula o WorkflowAgent com seus callbacks.
5. Execução
AsyncPostgresSaver + AgentFactory.create_supervisor()
Inicializa o checkpointer para persistência de estado do agente, cria o SupervisorAgent, e invoca supervisor.ainvoke(user_input, thread_id=session_id).
6. Finalização
collector.build() → persist_message() → complete_chat_turn_record()
O MessageCollector monta o AssistantMessage com todos os steps/subSteps coletados via callbacks. Salva no banco e marca o turno como concluído.
Event loop: Celery é síncrono mas o código de agente é async. A task usa asyncio.new_event_loop() e loop.run_until_complete() para rodar o código assíncrono de forma bloqueante dentro do worker.

SSE — como funciona o streaming

api/v1/chat.py (simplified)@router.get("/{session_id}/stream")
async def stream(session_id: str):
    event_bus = RedisEventBus(settings.REDIS_URL)
    channel = f"session:{session_id}"

    async def generate():
        async for message in event_bus.subscribe(channel):
            yield f"data: {message}\n\n"    # formato SSE

    return StreamingResponse(generate(), media_type="text/event-stream")

    case "sandbox_started": rightPanelStore.showFileExplorer();        break
    case "agent_end":       chatStore.finalizeMessage(); source.close(); break
    case "error":           chatStore.setError(data.content);          break
  }
}

Infraestrutura — Fluxo de Produção Completo

Browser
POST /api/v1/chat {session_id, message, datasource_ids}
Nginx roteia para backend-api:8000. auth_middleware valida o JWT antes do handler.
FastAPI
chat.py → run_agent_workflow.delay(agent_input_dict)
Cria ChatTurn no PostgreSQL, enfileira task no Redis via Celery, responde HTTP 200 imediatamente com turn_id.
Redis
Task queue + pub/sub para SSE
Broker de tasks Celery: celery:default queue. Canal de eventos: session:{session_id}.
Celery Worker
_run_agent_async() → SupervisorAgent.ainvoke()
Cria sandbox Docker, sincroniza arquivos, constrói tools, instancia agente com checkpointer PostgreSQL, executa o LangGraph loop.
LangGraph
agent → ToolNode(workflow_agent) → agent → ToolNode(summarize) → END
A cada token gerado, AgentCallback.on_llm_new_token publica no Redis → SSE → browser. A cada tool call, publica TOOL_START/TOOL_END.
WorkflowEngine
validate → topological_sort → execute nodes
Cada NodeHandler.execute(node, inputs, context) pode chamar o sandbox Docker via RuntimeControl:8010. Outputs persistidos em NodeRun.outputs no ExecutionContext.
MinIO
Artefatos finais armazenados: vídeo, dashboard, relatório
URLs retornadas nos outputs dos nós, registradas em WorkflowArtifact no PostgreSQL.
Browser
SSE agent_end → frontend fecha EventSource, renderiza artefatos
Painel direito exibe vídeo player, dashboard iframe e relatório. Workflow DAG mostra todos os nós como done.
